# Design charter

Version: 3 (approved 2026-11-17)

Seven rules for every code change in machinery and the product. One versioned copy lives in the repository (agents_extensions/shared/rules/design-charter.md, version line at the top); coding briefs and the reviewer checklist quote it from the trusted base branch, never from the PR under review. Each rule carries a status: LIVE (a CI check enforces it), PLANNED (check named, owner and milestone set; reviewers enforce it until then) or REVIEW-ONLY (no mechanical check is practical; reviewers enforce it). The security items in docs/best-practices/code-quality.md stay in force and are not replaced by this charter.

1. Settings, not constants. Host paths, account names, bot names, ports and hostnames come from one settings file per host. Code never names our host. Check: lint over machinery code for host-specific literals. Status: PLANNED (owner CTO, lint L1 after the census, milestone v0.4.0).
2. Tests own their data. Tests use fixtures, fakes and their own tmp_path; they never read live services, the real home directory or another test's leftovers. Real-store data is allowed only through validated read-only fixtures (tests/data_store_fixtures.py). Check: unapproved real-store or live-service access fails under the test runner. Status: PLANNED (owner CTO, check TESTS-OWN-DATA extension/L2, milestone v0.4.0; reviewers enforce until then).
3. Clean boundaries. Machinery never depends on product implementation modules or embeds product-specific paths or commands. Repository inspection and execution use documented orchestration interfaces with explicit target inputs. The product uses machinery only through its public API. Filesystem and subprocess coupling receive the same boundary checks as imports. Check: import-linter contract plus a lint for embedded product paths and commands in machinery. Status: PLANNED (owner CTO, lint L3, milestone v0.4.0; reviewers enforce until then).
4. Runs on a clean machine. Anything a component needs, it declares. The clean-machine drill kit runs on every machinery PR and proves packaging and declared dependencies; real integrations (GitHub, providers, the live host) are verified separately by their own canaries. Check: clean-machine CI job. Status: PLANNED (owner CTO, after the drill kit and its follow-up land).
5. A failing test is blocking evidence. A red test blocks until its cause is fixed, the test is corrected with evidence, or infrastructure recovery satisfies workflow.md's existing exception. Never use sleeps, retries, reruns or xfails to conceal a failure; synchronize on observable conditions with bounded timeouts. Check: CI rerun policy and test lint L4. Status: rerun enforcement LIVE only for the scope enforced by the machinery PR 711 lineage; owner CTO. Sleep and polling checks PLANNED (owner CTO, lint L4, milestone v0.4.0; reviewers enforce until then).
6. Delete before adding. Prefer removing code and duplicate sources of truth over adding layers, flags or wrappers. Status: REVIEW-ONLY (owner CTO; reviewers enforce).
7. Fail closed and say why. Validate external input and state at system boundaries; reject unsupported or invalid values with a typed reason. Never silently substitute a fallback. An explicit, documented default may handle an omitted optional input; it must not turn invalid input or unknown authorization, eligibility or safety state into permission to proceed. Status: REVIEW-ONLY (owner CTO; reviewers enforce; typed-refusal lint considered later if review data shows repeats).

Approval scope: this charter text, its placement (one versioned rules file, quoted from the trusted base in briefs and the reviewer checklist), and the lint plan L1-L4 as PLANNED items. Each lint still lands as its own reviewed PR.
